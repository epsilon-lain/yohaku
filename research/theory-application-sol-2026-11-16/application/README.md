## 本轮采用的“概念”是什么

设状态空间是两条有序自由约化关系词，图的每条边是一个冻结原始 move。以精确终点为中心完整计算半径为6的球，并为球内每个状态存最短后缀。查询结果可以复用：球内返回真实距离；球外返回7，得到函数

\[
h(s)=\min\{d(s,\text{target}),7\}.
\]

不可达状态的距离视为无穷。完整球使“未命中”也成为有证明的性质：至少还要7步。因相邻状态的距离差不超过1，此查询是一个可采纳、相容的距离下界。对已走原始步数为 \(g\)、已有合法上界为 \(U\) 的搜索前缀，\(g+h(s)\ge U\) 时，任何经过该前缀的路径都不能改善现有见证，因此可以安全剪去。词长cap32及计算预算是另外的启发式限制，会使搜索不完备。

这是可复用的性质查询及合法后缀接口，没有新增宏名字。找到13步是实际原始动作路径的改善，文件压缩比没有充当比赛步数。目标表的定义/构建成本也没有隐藏：336477个条目、570906次原始move计算；如果逐项存后缀，共1972206个move符号。没有证明整个算法更快或该表能在其他题上摊销成本。

## 方法修订与保留的负结果

1. 对旧17步路径任意两个顶点，完整构造各自半径3球，寻找长度不超过6的更短替换；没有找到。完整统计见 [local_check.json](local_check.json)。这不是17步全局最优证据。
2. 只把旧greedy的目标球半径从4升至6，仍返回17步，搜索计算4085次；完整目标球的额外构建费用须另计。
3. 改为保留已有见证、继续寻找改进，并使用上述截断距离安全剪枝。优先级是“总词长 + weight × 已走步数”，weight取0、0.5、1、2，每次最多200000次原始move计算，cap32；四次都找到13步，并均耗尽预算。完整成功、后续无改善、轨迹与计数见 [refinement_results.json](refinement_results.json)。这是同一开发例上的方法选择，不是四次独立测试。
4. 找到13步之后，自选完整半径6双向枚举，认证其最短性。观察员随后独立核验；协调者要求显式资源上限及可移植CLI，于是增加资源guard与来源参数。这些是外部反馈，不能记为自行涌现的组织分化。

## 最短性证书

[distance_certificate.json](distance_certificate.json)是首次完整证书；[distance_certificate_guarded.json](distance_certificate_guarded.json)是加guard后的完整重放，两份状态哈希一致。

| 球 | 各层新增状态数（半径0至6） | 总状态 | 研究实现 move 调用 | 官方逐边交叉核验调用 |
|---|---|---:|---:|---:|
| 起点球 | 1,14,145,1388,12895,117898,1068424 | 1200765 | 1852774 | 1852774 |
| 终点球 | 1,10,77,574,4453,35664,295698 | 336477 | 570906 | 570906 |

两球交集为空。14个move均有表列逆操作；如果存在不超过12步的路径，路径上必有一个顶点到两端距离都不超过6，因此必须同时属于两球。空交排除了全部0至12步，13步官方见证给出等号。两球均无词长剪枝、无状态等价商。生成边最大总词长分别为212、37。

[certify.py](certify.py)用独立tuple-word实现计算每条边，并逐边对照官方 `core.apply_move`。状态集合用明确编码排序哈希，可完整复算。观察员的 [独立结果](../observation/independent_ac_result.json)与本证书的层数、见证及官方收据一致；其实现未导入本队搜索或证书代码，见 [对照记录](independent_comparison.json)。这种独立实现仍共享冻结官方动作规范，不是对规范本身的独立形式化证明。

成本分列在 [costs.json](costs.json)：目标表编译570906次；四次搜索共800000次；证书研究实现2423680次加同数官方交叉核验；guard重放再各同数；观察员独立枚举另2423680次官方move调用。旧路径局部审查、探索与低预算检查单列。move计数不包含哈希、排序、队列、Python内存等完整运行费用。没有整体加速结论。

## 复现与资源边界

Python3.10+，标准库；从本阶段根目录运行。先准备固定上游与旧baseline目录，再通过参数指定，代码不含工作区绝对路径：

```sh
python application/refine.py --official-root /path/to/ac-official --baseline-root /path/to/baseline
python application/certify.py --official-root /path/to/ac-official --baseline-root /path/to/baseline --max-seconds 30 --max-states 1600000
python application/verify_witnesses.py --official-root /path/to/ac-official --baseline-root /path/to/baseline
```

证书默认总状态上限1600000、墙钟30秒；完整两球实际1537242状态。若达到限制，输出 `status: incomplete`、`exact_AC_distance: null`，不给下界证明。资源失败检查见 [resource_limit_check_portable.json](resource_limit_check_portable.json)。机器负载可能使30秒不足，此时需要提高允许预算并重新完整构造，不能把部分空交作为证书。

初版完整证书及guard版已真实完整运行；最终可移植参数改动后，以低预算搜索、来源校验、资源截断及两条官方见证/CLI重放验证，没有再次重复百万状态枚举。历史发布快照保留原始代码，当前代码保留相同枚举逻辑并增加参数及来源检查。
