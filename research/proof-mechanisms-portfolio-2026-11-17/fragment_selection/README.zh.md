# 固定证书候选图：最大单次收益与 Pareto 组合

本轮把已证明的固定候选 DAG 选择算法落实成有界实验。**29 例上 Pareto DP 与同图贪心的 length/work/peak 全部相同，未找到真实 AC 证书上的组合优势。** 两者把同一批原证书总长度 465 压到 400；这不证明全 AC 最短，也不把原有清理或符号规则的收益归功于 DP。

只使用固定官方提交 `a0fd6e6f52d82c93ccc06ab91d81e8fa3678256e`，直接 compile 核过 Git blob 的 canon/core/stable_core 源码，不使用不确定 pyc。本轮为云端独立实验，没有连接或启动本机 Yohaku，没有平台上传、排行榜访问或本队直接 GitHub 写入。旧 v1 保留四例 0234/0316/0154/0107 的动作没有索引、重放或分析。

## 同一个候选图的含义

先从同一原证书完整重放得到精确状态 `S_0,...,S_N`。顶点是原位置而非状态等价类，故重复状态仍保留不同位置。每条候选边 `i→j` 必须有 `i<j`，并逐步用官方 apply 展开，从完整有序、自由约简、含 rank 的 `S_i` 精确到达 `S_j`；同构、改名、整体共轭均不算相等。所有原始相邻边在有限生成开始前保留。

候选来源依次为：精确重复状态的空路线、已冻结11条 rank2 符号子串规则、共同共轭框架v1、全部257个1原语尝试、整体对象左乘3步、donor共轭4步，以及自由约简 `|h|≤2` 的 `h v^(±1) h^-1` 共轭展开。枚举目标、不同 donor 与两符号。所有原语尝试，包括不适用者，都真实计费。外部规则匹配仅使用原动作与原状态，不根据改写后的状态生成新边。

符号规则来自 [symbolic_rules](../symbolic_rules/README.zh.md)，冻结 hash 见 FREEZE；共同框架纯生成器逐字采用 [frame_rules.py](frame_rules.py)，hash为 `c903775f...`。sym-dev-010/011与共同共轭框架同族，不计成独立机制。相同 `i,j,expanded route` 合并成同一边，保留多重来源。稍后的 pending-frame v2未接入；它的唯一旧真实命中已被sym-dev-010覆盖，不改变本轮冻结规则。

不要求候选比原区间更短、work更低或peak更低。实际731条去重边包括465条原相邻边，按相对原区间动作数分为48条更短、508条相等、175条更长；190条候选的局部work或peak有所上涨，仍保留。例：0108的边21将原[11,16)替成[2,5,3]，长5→3，局部work增加1、peak增加3；是否可选由完整路径预算决定。仅把任何中间总词长超10000的展开排除，避免把端点恒等当成资源合法。

每边记录 `length = 展开步数`，`work = 展开后状态长度之和，不含入口`，`peak = 含入口的最大总词长`。完整路径的work为初态长度加各边work，peak为初态与各边peak的max。资源上限为length100000、work5000000、peak10000、rank≤8。

贪心从原相邻边路径开始。每轮只考虑入口、出口仍在当前路径上的冻结边，用它替换两端间的当前子路径；允许覆盖已选替换，但不重新生成候选，也不能使用已删去的顶点。仅接受完整路线严格缩步且全局预算合法者，按替换后 `(length,work,peak,start,end,expanded route)` 排序取最小。如此定义的“最大单次收益”与固定图反例一致。

DP按原顶点顺序维护 `(length,work,peak)` Pareto标签，加法更新length/work，max更新peak；超预算标签删除，同顶点逐项不劣的标签支配另一标签。终点取三项字典序最小者，同三项平局保留先生成标签，不保证动作列表字典序最小。加法与max保持逐项不等式，且精确端点让同顶点未来可用边相同，因此支配剪枝正确。

两选择器读取同一序列化图，结果内图SHA-256一致，没有分别构图，没有“重建后动态贪心”的不同候选图对照。没有触及DP标签/转移截断时，DP最优只在**实际已生成的固定DAG**。图外路线、改写后新产生的候选、任意AC路线均不在保证内。本批29例配置库均枚举完，但有限宏库并不完备。

## 预算、冻结与局限

开发前固定每例40000次official search apply：21开发+8测试共预留1160000，另预留诊断100000、未分配失败余量240000，团队总cap1500000。开发重试累计占原例预算，不重置。verification预注册为团队全局15000 cap，每例计划原证书/贪心/DP三次完整重放；没有另设每例verification硬cap。实际每例不超过60次。

图cap10000边；DP每顶点最多2048标签、每例最多2000000转移。若图截断，仍只可声称在已生成图选择；若标签或转移截断，取消DP最优声明。实际29例均没有图、调用、标签或转移截断；每顶点最终仅1个标签，累计接受512个中间标签，累计731次DP转移，终点各1个Pareto标签。并未在真实数据上遇到需要多标签保留的资源竞争。

实际search为342096次：诊断576、开发253648、测试87872；verification为1265次：开发937、测试328。包括所有不适用动作尝试、两次开发期自检、完整官方verify内部调用。候选路线开始150920次；其中不适用原因分别为relator_out_of_rank101078、generator_out_of_rank10870、destabilize_precondition778。符号账另记录3868次规则子串比较、框架215次自由约简调用/335次输入字母访问；这些是明确计量单位，不把普通Python算术冒充官方apply或完整CPU成本。

同预算指两个选择器共享每例同一受40000调用上限约束的构图结果，不是分别花40000调用；贪心/DP之后都无官方search调用，完整输出验收另计。DP计算上限与贪心计算不同，不主张相同CPU时间或速度/token收益。旧baseline另有旧预算，不混入同预算主比较。

`FREEZE.json`写于2026-11-17T11:34:22.963628Z，随后11:34:34写`TEST-ACCESS.json`才索引新8动作。代码/配置/接入规则的hash冻结后未变，没有按测试结果调参、扩样或补规则。[METHOD-LOG.md](METHOD-LOG.md)保留实际沟通、审查、两次诊断与一个零官方调用的报告阶段KeyError修正；[attempt-ledger.json](attempt-ledger.json)保留全部正式命令与累计调用。
