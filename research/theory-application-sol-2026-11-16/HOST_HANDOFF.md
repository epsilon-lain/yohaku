# Yohaku 原宿主的接续配置

状态：这是可执行前的接续说明与请求配置校验器，**尚未在原 Yohaku 宿主执行**。本目录实际研究运行在 ChatGPT Work 协作环境。不能用这里的启动记录声称原宿主进程已停止、迁移或更换模型。

## 已授权的新要求

- 两个研究队：理论队研究框架的数学性质与结论；应用队研究在 Andrews–Curtis 的应用、合法路径与压缩。
- 研究模型固定 `gpt-6.1-sol`；最低 `high`，允许更高努力，本轮负责人为 `max`，协作者及外部复核至少 `high`。不用 Astra，不使用 GLM、Gemma 或 DeepSeek。
- 用户允许 Sol 的 Max/Ultra 上限。本轮只选择 Max；Ultra 必须按实际产品支持的模式设置，不能把界面模式名盲目填进不支持它的 API 参数。
- 共享数学结果、代码、反例、失败与精确版本，分别保存两队组织档案；观察真实任务安排、求助、复核、方法修订及采用链。组织变化不用角色数量代替。

## 宿主接续顺序

1. 读取原实验登记、监督器、任务与资金记录，记录当前实际版本和在途状态。为旧低于模型下限的节点暂停**新的派发**，保留其日志、回执和原负责人身份。
2. 对已在途请求按原恢复规则查询或等待；未知结果保留责任，不重放可能已经发送的 POST。不要用删除记录、重置账本或旧预留退款伪装完成迁移。
3. 新建关联旧记录的新研究阶段，不能把任务与模型均改变后的结果混作原免疫／自主组织独立对照。检查 Codex 的实际模型选择、努力设置和现有授权会话；不复制账号密钥，不新购 API 额度。原服务 Credits 不能直接视作另一计费系统的可用余额。
4. 在每个负责人、协作者创建与每次请求前执行模型门禁。可先检查：

   ```sh
   python3 model_policy.py --model gpt-6.1-sol --effort max --surface codex
   python3 model_policy.py --model gpt-6.1-sol --effort high --surface codex
   ```

   任一模型不在允许范围、努力低于 High、必要能力不可用，或存在自动弱模型 fallback 时停止派发并报告。此脚本不会自己修改原运行器，必须接入真实准入路径，不能只运行一次就声称所有请求已受控。
5. 导入共同种子及本轮已核验结果，保留来源与版本；给两队相同数学入口，允许按需检索和读取，精确记录外部新增知识及实际采用。
6. 使用原生任务、文件和模型事件观察工作流；区分模型选择下一任务、宿主中性接续、宿主修复、外部复核与模型自述。导出后公开必要投影，保留私有原包。
7. 完成真实启动后回读模型请求配置、首个完整终态、文件与实际任务 ID。若客户端没有返回供应商实际模型或 token，不得填造；明确只能证明配置还是还能证明实际回执。

上述步骤需要原宿主环境。这里没有访问该机器的运行目录，因此没有执行旧进程控制，也没有消耗原 Adaption 授权余额。

## 本轮模型资料来源

已读取的[官方 Sol 模型文档](https://developers.openai.com/api/docs/models/gpt-6.1-sol)列出 `high`、`xhigh`、`max` 努力参数；[Codex 模型选择说明](https://learn.chatgpt.com/docs/models?surface=cli)说明显式模型选择。账户实际可用性仍以宿主客户端为准。本轮协作工具另外支持 Ultra 配置，但未选择它。
