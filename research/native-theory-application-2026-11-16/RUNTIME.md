## 原生任务与续行

`COMPLETE-RECEIPTS.json` 包含三个持久节点的四项任务记录。将其与 `CURRENT.json`、门禁状态和原始 task traces 交叉核对后：

|---|---|---|
| 总负责人首任务 | 完成 | `done`、`output_complete=true`、`commit_confirmed=true`、`native_cleanup_complete=true`；原生子进程退出码 0 且已回收；匹配 thread/turn 的原始 `turn/completed` |

三个首任务各有原生 node → task → thread → turn 的绑定证据。完成回执限定于这些首任务，不表示整个研究计划结束。

总负责人续行沿用其首任务的原生 thread，使用不同 turn。原始 trace 明确记录 `thread/resume`、`catalog_matches`，随后有 turn acknowledgment。知识事件 #396 记录其主动 `research_continue`，门禁事件 #193 记录 `route=continuation` 的实际派发；队列状态为已派发。因此续行是真实原生活动，但附件不能支持“续行已经完成”。
