# 可还原边界编码：把区间操作变稀疏后的完整账本

这是整数有限序列的标准差分机制。净收益来自**每次长区间加法在新表示中只改一至两个边界**，不是减少信息维数。保留一个边界值后，转换、批量更新、还原、相同最终全数组输出都能完整计费。本文没有调用任何官方 AC 动作，也不把这个算术例子外推为 AC 比赛改善、数学首创或普遍 CPU 加速。

概念桥梁是区间覆盖与离散微分/积分：区间指示序列的差分只在跳变边界非零；前缀求和还原水平值时，需要保留一个初值。

## 对象、目标与可逆性

给定整数 `n≥1`、整数数组 `a=(a_0,…,a_{n−1})∈Z^n`，以及按输入次序给出的 `Q≥0` 次更新 `(l_j,r_j,v_j)`，其中 `0≤l_j≤r_j<n`、`v_j∈Z`。一次更新将 `a_i` 加上 `v_j`，恰好作用于闭区间 `l_j≤i≤r_j`。比较目标固定为：从同一原数组开始执行全部更新，只在最后输出整个同一整数数组；不要求中途查询。

定义 `d_0=a_0`；对于 `1≤i<n`，定义 `d_i=a_i−a_{i−1}`。共保留 **n 个整数**。逆映射是 `a_0=d_0`、`a_i=d_0+⋯+d_i`，因为相邻减项逐项抵消。原地编码按 `i=n−1,…,1` 的顺序执行 `buffer[i]−=buffer[i−1]`；原地恢复按 `i=1,…,n−1` 执行 `buffer[i]+=buffer[i−1]`。这两个方向分别保证读取尚未覆盖的原左邻居和已经恢复的左前缀。`n=1` 时两个循环均为空。

对于一次 `(l,r,v)`，编码后执行 `d_l+=v`；若 `r+1<n`，再执行 `d_{r+1}−=v`。理由是区间内部的相邻两个值同时增加 `v`，其差不变；左端差增加 `v`，右端外的差减少 `v`。当左端是 0 时，第一项恰好更新保留的 `d_0`；当右端是 `n−1` 时，不需要存放数组外的消失事件。

如果只保留内部差 `(a_1−a_0,…,a_{n−1}−a_{n−2})`，常量偏移会丢失。精确反例：`(0,1,0)` 与 `(5,6,5)` 的内部差都为 `(1,−1)`，即使 `Q=0`，正确输出已不同。两者接受同一次 `(1,2,−1)` 后，输出分别是 `(0,0,−1)` 与 `(5,5,4)`，内部差仍相同。一般来说，内部差相同恰好意味着两数组相差一个常量数组；保存 `a_0` 正好补回这部分信息。这里没有丢掉核之后冒称可逆。

## 明确的成本模型

每次**数组数值**的整数二元加法或减法各计 1；如果显式计算相反数，则按 `0−v` 再计 1。本实现直接二元减 `d_{r+1}−v`，因而显式取负次数为 0；输入已经提供有符号整数 `v`。不把减法分解为一个未计价的取负加一个加法。

复制也单列：两种算法都从保留的原始输入复制 `n` 个整数到工作数组，最后都复制/发射 `n` 个最终整数。原地转换与还原没有另一个长为 `n` 的拷贝。每次算术结果仍会写回一个单元，写回次数在结果中明确记录，已包含于该算术原语，不再重复加价。两算法均有 `n` 个工作单元和 `n` 个输出单元，原始输入也保留。若调用者直接提供可覆盖的输入，可同时省去两者的 `n` 次输入复制；比较差额不变。

记 `S=Σ_j(r_j−l_j+1)` 为所有区间长度之和，`K=#{j:r_j<n−1}` 为右端尚有数组内边界的更新个数。完整账本如下；`Q`、`S`、`K` 只用于说明和核验，算法不先算这些统计量。

| 阶段 | 原空间逐元素法 | 可还原差分法 |
|---|---:|---:|
| 原始输入复制到工作数组 | n 次复制 | n 次复制 |
| 表示转换 | 0 | n−1 次减法 |
| 全部更新 | S 次加法 | Q 次加法、K 次减法 |
| 还原到原数组 | 0 | n−1 次加法 |
| 最终完整输出 | n 次复制/发射 | n 次复制/发射 |
| 数值算术合计 | S | 2(n−1)+Q+K |
| 算术加复制/发射各为 1 的合计 | S+2n | 2(n−1)+Q+K+2n |

因此，**完整转换和恢复以后仍严格省数值算术，当且仅当 `S>2(n−1)+Q+K`**。这也是加入共同复制/输出后的严格优势条件。

任意区间都满足 `S≤Qn`、`K≥0`，因而节省量至多 `(Q−2)(n−1)`。所以在本模型中，`Q≤2` 对任意初值、任意合法区间都不可能严格省；下文小域的零胜例与这个一般界一致。

这是数据算术模型，不是全部机器指令账本。循环、索引（包括代码中的 `r+1`）、比较、分支、输入解析、测试统计和哈希均不在这些数值算术单位中。输入、输出以及工作存储的复制已单独展示；实际 Python 代码还包含为了核验而插入的计数与断言，因此不能拿运行时间当两种算法的基准。

## 严格收益族、精确阈值与不省的对照

若所有操作都是全区间 `[0,n−1]`，则 `S=nQ`、`K=0`，算术差额为 `(n−1)(Q−2)`。所以 `n≥2` 时，`Q≥3` 才严格省，`Q=2` 平，`Q≤1` 反而亏；`n=1` 时两者始终相同。相同区间还可以先合并更新值，因此这里明确只与题设的逐元素基线比较，**不声称击败允许任意离线重排/合并的最优算法**。

一个区间各不相同的族是：令 `Q=n`，依次执行每个后缀 `[j,n−1]` 加 1，`j=0,…,n−1`；初始整数数组可以任意。逐元素法为 `n(n+1)/2` 次加法；差分法为 `3n−2` 次加减；净省 `(n−1)(n−4)/2`。因此整数 `n≥5` 严格省，`n=4` 平，`n=2,3` 亏，`n=1` 平。若取 `n=100`、`a_i=i−50`，完整输出就是 `b_i=2i−49`。

| 固定实例（均完整还原后输出） | 直接更新算术 | 转换 / 边界更新 / 恢复算术 | 差分算术合计 | 每法共同复制与输出 | 加入复制输出后的直接 / 差分 | 净省算术 |
|---|---:|---:|---:|---:|---:|---:|
| n=1000，a_i=i−500，200 次全区间加 1 | 200000 | 999 / 200 / 999 | 2198 | 2000 | 202000 / 4198 | 197802 |
| n=100，a_i=i−50，每个不同后缀加 1 | 5050 | 99 / 100 / 99 | 298 | 200 | 5250 / 498 | 4752 |
| n=1000，同一初值，200 次单点 [500,500] 加 1 | 200 | 999 / 400 / 999 | 2398 | 2000 | 2200 / 4398 | −2198 |

第一行输出 `b_i=i−300`；第二行输出 `b_i=2i−49`；第三行仅 `b_500=200`，其他位置保持 `b_i=i−500`。这些确定公式规定全部输入和输出；`checks.json` 另存它们的规范化输入/输出 SHA-256。第三行说明：若原操作已稀疏，差分可能将一次写入变成两个边界写入，并额外支付转换/恢复。

更一般地，若每次都是固定长度 `L`、右端是否在数组内有下一项的指示量为 `e∈{0,1}`，则严格条件是 `Q(L−1−e)>2(n−1)`。只有 `L>1+e` 时才可能靠增加批量大小抵消转换开销。

## 整数位长与适用目标

令 `A=max_i|a_i|`、`T=Σ_j|v_j|`。逐元素法的每个数组值绝对值始终至多 `A+T`；差分转换后的值至多 `2A`，边界更新后至多 `2A+T`，恢复出的值又至多 `A+T`。这里 `v_j` 自身的绝对值也不超过 `T`。采用 `w(x)=1+bit_length(|x|)`（一个符号位，零宽度为 1）的统一宽度，分别至多 `1+bit_length(A+T)` 与 `1+bit_length(2A+T)`。这是上界，不是每个单元均取此宽度；输出的真实宽度也必须支付。

`checks.json` 记录实际运行中最大绝对整数和上述符号位宽。较大全区间例两法最大宽度都是 11；单点亏损例两法都是 10；后缀例两法都是 9。在固定小域里，差分可出现宽度 4，逐元素最多 3，说明不能把每次整数运算的真实位成本无条件视为相同。标准位模型下，加减通常还需与操作数位长成正比的工作，复制和输出也依位长计费；本文的单位算术优势不自动给出每台 CPU 的用时优势。

收益依赖后续任务：

- 当前目标只在批量结束输出一次，所以一次转换和一次恢复可摊到整批更新；若本来就以差分输入或只要求差分输出，转换/恢复中的相应项可另行省去，但那是不同接口。
- 若每次更新后都要完整快照，保留差分状态时，每张快照还要做 `n−1` 次前缀加法、初始化一个前缀累加器的复制，以及 `n` 次输出。原来只支付一次的恢复不能继续只算一次。
- 原数组单点读取只需读取一个单元；差分表示中的第 `i` 项查询需要从 `d_0` 做 `i` 次前缀加法（另有初始累加器复制）。大量在线单点查询可能吃掉更新的收益；若另加树状数组等索引，其构建、维护和查询要重算。
- 原数组单点更新只需 1 次加法；差分通常需 2 次，仅更新最后一项时需 1 次。此类更新不靠差分变便宜。
- 一般区间求和、最大值、依赖当前 `a_i` 的条件更新、排序等目标，并未由这组边界自动变成常数次操作；不能把恢复成本或额外索引成本忽略。如果只求一个总和，还可用其他标量统计量，已不是本例的相同全数组输出目标。

与研究问题的联系仅是：**改变表示后，哪些运算变稀疏；保留哪些辅助信息才能回到同一精确目标；转换、更新、恢复、输出整条链是否仍有净优势。** 这里逐项展示一个可证收益族、一个亏损族和一个不可逆反例，不以“结构更简洁”代替完整成本比较。

## 有限核验与复现

运行 `python check.py`，仅用 Python 标准库，写出 `checks.json` 与 `SHA256SUMS`。固定穷举范围**没有抽样**：所有 `n=1,2,3,4`，所有 `a_i∈{−1,0,1}`，所有长度为 0、1、2 的有序区间 `±1` 更新序列。各维初值数量 `3^n`，操作字母表大小 `n(n+1)`，各维例数分别为 21、387、4239、34101，合计 **38748**。

每例独立检查逐元素实现、原地差分实现、按坐标闭式 oracle 的全数组一致性，核对加减数、复制数、位长上界，并把有序输入、输出和账本写入滚动 SHA-256。小域因 `Q≤2` 的完整开销，严格胜例为 0，平例为 489，亏例为 38259；累计数值算术是直接法 147306、差分法 341724，这是如实保留的负结果。严格收益另用预先声明的 `Q=3` 阈值例、不同后缀例与大实例核验。另加 10 个命名例（含大整数正负更新、零更新）和 2 个不可逆反例的非空更新运行，总完整算法核验 **38760** 例，低于 synthetic case cap 200000。
