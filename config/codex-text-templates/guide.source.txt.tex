# Codex text operator: content, send and stop

This template contains no account, request history or acceptance result. The installed code is codex-text/3 with save-feedback/2. Each source path binds its own independent task. Ordinary Socius chat configuration is separate.

Read the current source and whole-source revision. In one body-only patch, replace the input region with your content and set the control region to ka (the current wire value for send). Keep result unchanged. Saving and successful Loom sync form the persistent submission boundary. No specific word is required inside the content; input text never acts as control. A separate draft save is optional. Stop by changing only control to stop and saving the latest revision.

Keep each of the six delimiter lines unique. Escape a delimiter-looking input line with a leading backslash, and double an existing leading backslash. Preserve multiline content and trailing newlines. Use exact unique body patches, or coordinates from the same read_range view/revision; body and text are different 1:1 origins. Coordinates are Unicode scalar positions and end-exclusive. Re-read after conflicts or after a save hook changes the document.

Separate saved/save_status and saved_revision from submission (accepted, pending_confirmation, not_applied) and authoritative execution_status. Workspace busy or a missing reply does not prove that no task started. Preserve the input and query the existing page/request/details; replay_allowed=false forbids automatic resending. An explicit new send after a known terminal result starts a new request, even for the same content.

The compact /3 result links to per-request details; long reply text is truncated with reply_truncated. Rust chat objects and host task/process receipts remain authoritative. Never edit result to claim success. Completion clears input once only if it still matches the submitted snapshot and control=draft; newer drafts and successor controls are protected by CAS.

save-feedback/2 scopes diagnostics to the saved source revision/action. A recovered acknowledgement for that same operation stops projecting its transient warning. Real not_applied rejections remain visible. Legacy unscoped notices remain in details as legacy_notice. Normal cancelled/error=stop is compactly displayed as cancellation, while raw authority/worker details retain their original fields. Other execution errors remain visible.

Stop acceptance is distinct from confirmed cancellation. Confirm status=cancelled, execution=ended, cancel_confirmed and native process cleanup. A task that finished before Stop is done, not cancelled. Unknown cancellation outcomes are queried without issuing a second cancel. A cancelled worker's transport interruption is not a second authoritative task failure.

Readiness is a timestamped per-source observation with observed_at and expiry; missing/stale state is unknown. It does not authorize a new task or replace process authority. This source checkout ships services disabled. See README.md and docs/INTERNAL-UPDATE.md in the source repository for first-time opt-in setup and the fixed internal update workflow. No model login or request occurs merely by building the package or installing these draft templates.
